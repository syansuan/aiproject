前端转 AI 第一课：大模型其实是个会中途断线的异步接口

干了 7 年的前端，想着转全栈，看着 Boss 上的岗位，感觉全栈也危，准备一步到位学 AI，讲一下手搓 AI 遇到的坑吧。

用原生 fetch 手写大模型流式输出时，我踩了三个坑：

## 1. reader 不是可迭代对象（while(true) + read()）

接口返回的不是一个 JSON，而是一个 `ReadableStream` 字节流。我用 `for...of` 去遍历 reader 直接报错——它不是可迭代对象，只能 `getReader()` 拿到 reader，再用 `while(true)` + `await reader.read()` 一块一块读。这跟我写了 7 年的"await res.json() 一次拿完"是完全不同的编程模型。

怎么证明它是真流式而不是一次性到达？我写了个不开浏览器的测试（`npm run smoke`），原理是拦截 `textContent` 的每次写入：

## 2. split('\n') 切的是协议，不是正文

我原以为 `split('\n')` 拿到的数组就是网络分块的样子，以为它在处理"内容里的换行"。**不对。`\n` 不是内容，是 SSE 协议的分隔符**——服务端规定每条消息必须以 `data: ` 开头、以 `\n\n` 结尾，你切的不是句子，是**协议格式**。这才是"前端思维"错的真正原因：不是把它当成普通返回体，而是**把协议分隔符当成了正文标点**。

半行的成因是**网络切分点落在字节流中间，是随机的**——服务端发的是完整的，是 TCP 把它从任意位置掰开了。`split('\n')` 之后最后一段后面没有 `\n` 封口，所以可能是半行；`pop()` 是把它挪回 buffer，等下一轮拼全。**段数 = \n 的个数 + 1**。

## 3. 什么错该重试：401 vs 429 vs 5xx

报错体长这样：`{"error":{"code":"1211","message":"模型不存在，请检查模型代码。"}}`。外层 HTTP 状态码决定要不要重试，内层 code 决定问题在哪。**重试的前提是"这个错可能是暂时的"**：429 是被限流，等一会儿再来就行；401 是 Key 错了，再发一万次结果也一样，所以不重试。我的判断逻辑里，429 和 5xx 归为同一类——可重试；400/401 归为另一类——直接报错。但报错信息要给全（状态码 + 内层 code + message），不然用户根本不知道是 Key 的问题还是参数写错了。还有一点：重试的退避必须是**指数递增**的（1s → 2s → 4s），否则就是在持续捶打已经过载的服务端。

**另外发现一个边界**：智谱 `temperature` 范围是 `[0,1]`，传 1.5 直接 400，和 OpenAI 的 `[0,2]` 不一样——换平台时参数得重设。

整个体验下来，大模型就是一个又慢、又贵、还会中途断线的异步接口，我们会的这些重试、退避、中断、超时全都得用上。所谓"转 AI"，不是把前 7 年的东西丢掉重学，是把它们换个地方用。
